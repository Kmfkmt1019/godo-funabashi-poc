# オフライン対応 検証PoC — セットアップ手順書

対象: `PoC_指示書_オフライン対応検証プロダクト.md` の実装物
※本番実装ではありません。CP3には一切接続しません。すべてダミーデータです。

初心者エンジニアの方でも迷わないように、コマンドライン操作ゼロ（ブラウザ操作だけ）
でデプロイできる構成にしてあります。

- ダミーサーバ: **Google スプレッドシート + Google Apps Script（GAS）**
  → サーバーを借りる／立てる作業が一切不要。届いたデータはスプレッドシートの
  行としてそのまま見える。
- クライアント(PWA): **GitHub Pages**
  → ファイルをアップロードするだけでHTTPSのURLが手に入る。

## Step 1: ダミーサーバ（GAS）をデプロイする

1. Google スプレッドシートを新規作成する（[sheets.new](https://sheets.new) を開くだけ）
2. メニュー「拡張機能」→「Apps Script」を開く
3. 最初から入っているコードを全部消して、`gas/Code.gs` の中身を丸ごと貼り付ける
4. フロッピーのアイコン（保存）を押す
5. 上部の関数選択プルダウンで `setup` を選び、▶（実行）を押す
   - 初回のみ「承認が必要です」と出るので、自分のGoogleアカウントで許可する
   - 実行後、スプレッドシートに `Master` と `Events` の2つのシートができていればOK
6. 右上「デプロイ」→「新しいデプロイ」
   - 歯車アイコン → 種類「ウェブアプリ」を選択
   - 「次のユーザーとして実行」: **自分**
   - 「アクセスできるユーザー」: **全員**
   - 「デプロイ」を押す
7. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/.../exec` の形）をコピーする

> Code.gsを後から修正した場合は、「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →
> バージョンを「新バージョン」にして再デプロイしないと、公開中のURLには反映されません。

### 動作確認

コピーしたURLの末尾に `?action=master` を付けてブラウザで開いてみてください。
（例: `https://script.google.com/macros/s/xxxxx/exec?action=master`）
ダミーの配合予定4件がJSONで表示されれば成功です。

## Step 2: クライアント側にURLを設定する

`js/api.js` を開き、1行目付近の

```js
var GAS_URL = 'https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID_HERE/exec';
```

を、Step 1でコピーした自分のURLに書き換えて保存してください。**この1ファイルだけ**
書き換えれば、画面A/B/Cと重量モックの両方に反映されます。

---

## Step 3: クライアント(PWA)をGitHub Pagesにデプロイする

1. GitHubアカウントを持っていない場合は [github.com](https://github.com) で作成する
2. 右上の「+」→「New repository」で新規リポジトリを作成（例: `godo-funabashi-poc`）
   - Public / Private どちらでも可（Privateでも Pages は無料で使えます）
3. リポジトリ画面の「Add file」→「Upload files」を開く
4. `poc-godo-funabashi` フォルダの中身（`index.html` や `js/` フォルダなど）を
   **フォルダごとドラッグ&ドロップ** してアップロードする
   - `README.md` や `gas/Code.gs` は配信不要ですが、混ざっていても害はありません
5. 「Commit changes」でアップロードを確定する
6. リポジトリの「Settings」タブ →左メニュー「Pages」
   - 「Build and deployment」→ Source: **Deploy from a branch**
   - Branch: **main** / フォルダ: **/(root)** を選んで「Save」
7. 数十秒〜数分待つと、ページ上部に
   `https://<あなたのユーザー名>.github.io/<リポジトリ名>/` というURLが表示される
   → これが **iPadでアクセスするHTTPS URL** です

## Step 4: iPadで実機確認する

1. iPadの **Safari**（他のブラウザ不可）でStep 3のURLを開く
2. 下部の共有アイコン（□に↑）→「ホーム画面に追加」
3. ホーム画面に追加されたアイコンをタップして起動する
   - タブのまま使うと **7日でデータごと消えます**（ITP対策のため必ずアイコンから起動）

以降は指示書 **§5 合否チェックリスト** の手順（機内モードON/OFF、アプリの完全終了など）
に沿って確認してください。このPoC実装は #1〜#13 すべてに対応しています。

### 重量モックの使い方（あると良い #12・#13）

1. ホーム画面のアプリ(画面C)を下にスクロールすると「重量モックを開く」という
   リンクがあるので、そこから `weight-mock.html` にアクセスする
   （`weight-mock.html` 側にも「← 通常の記録アプリに戻る」リンクがあります）
2. バケット番号を選び「投入シミュレーション開始」を押すと、
   `34,900 → 36,900 → 38,500 → 40,100`(kg) の重量変化を3秒間隔で再現します
3. 画面Bで同じタイミング・同じバケットに近い重量（±100kg以内）を入力すると、
   サーバ側（スプレッドシートの `Events` シート）の `match_status` 列が
   自動で `matched` になります
4. 同じ重量を2回連続で投入・入力すると、あえて一意に決められず `要確認` に
   なることも確認できます（#13）

突合結果はスプレッドシートを直接開くのが一番わかりやすいです
（`?action=received` のJSONでも確認できます）。

## §5 合否チェックリストの埋め方

指示書 §5 の表をそのまま使ってください。結果欄に ○/×/未実施 を記入するだけです。
特に **★の2つ（#5: 閉じていると送られない／#6: 開いた瞬間に送られる）** が
このPoCの核心なので、必ず確認してください。

| # | 確認内容 | このPoCでの対応箇所 |
|---|---|---|
| 5 | 閉じていると送られない | Background Syncを実装していないため、アプリを完全に閉じている間は`sync.js`のどのトリガも発火しません |
| 6 | 開いた瞬間に送られる | `app.js`/`weight-mock.js` の起動処理最後で `syncQueue('app-launch')` を呼んでいます |
| 7 | 前面復帰は自動 | `visibilitychange` と `online` イベントで `sync.js` が自動発火します |
| 8 | 二重登録されない | `client_uuid` を `Events`シートで照合し、既存なら `skipped` を返します（`gas/Code.gs`） |

## トラブルシューティング（指示書 §8 抜粋 + 本実装固有の注意）

| 症状 | 対処 |
|---|---|
| Service Workerが登録されない | GitHub PagesのURLは自動でHTTPSになっているはずですが、`http://`でアクセスしていないか確認 |
| iPadでホーム画面追加が出ない | Safari以外（Chrome for iOS等）で開いていないか確認 |
| POST(`いま送る`)が失敗する / CORSエラーが出る | ①GASの再デプロイをし忘れていないか ②アクセス権限が「全員」になっているか を確認。`js/api.js`は意図的に`Content-Type: text/plain`で送ってブラウザのプリフライト(OPTIONS)を回避しています |
| `?action=master` を開いてもJSONが出ない | Apps Scriptエディタで`setup`関数を実行し忘れている可能性。もう一度実行してください |
| データが7日で消えた | タブのまま使っていた可能性大。必ず「ホーム画面に追加」したアイコンから起動してください |

## このPoCでやっていないこと（意図的な割り切り）

指示書 §6 の通り、以下は対象外です。

デザイン／複数端末の同時操作・競合解決。
